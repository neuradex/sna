HTTP API는 세 가지 표면으로 묶임: **세션** (세션 레코드의 CRUD),
**에이전트** (spawn된 프로세스의 라이프사이클과 제어), **권한**
(승인 흐름).

## 세션

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `POST` | `/agent/sessions` | 세션 레코드 생성 (아직 프로세스 없음) |
| `GET` | `/agent/sessions` | 세션 나열 (`?include=chain` 으로 runtime 히스토리도) |
| `PATCH` | `/agent/sessions/:id` | 라벨, meta, cwd 갱신 |
| `DELETE` | `/agent/sessions/:id` | 세션 삭제 (히스토리도 제거) |

## 에이전트 라이프사이클

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `POST` | `/agent/start` | 세션 안에 에이전트 spawn |
| `POST` | `/agent/send` | 메시지 전송 (`images[]` 지원) |
| `POST` | `/agent/resume` | 프로바이더용 정규화 히스토리 재구성하고 재시작 |
| `POST` | `/agent/restart` | 같은 `Session.config`로 re-spawn (옵션 오버라이드 가능) |
| `PATCH` | `/agent/session` | `{cwd, model, permissionMode}` 통합 mutator |
| `POST` | `/agent/interrupt` | 현재 턴 취소 (프로세스는 유지) |
| `POST` | `/agent/set-model` | 런타임 도중 모델 변경 |
| `POST` | `/agent/set-permission-mode` | 런타임 도중 권한 모드 변경 |
| `POST` | `/agent/kill` | 에이전트 종료 (세션 레코드는 유지) |
| `GET` | `/agent/status` | 세션 상태 스냅샷 |

## 단발 호출

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `POST` | `/agent/run-once` | spawn → run → 결과 반환 → 정리 |
| `POST` | `/agent/run-once/stream` | 같은 라이프사이클, `AgentEvent`의 SSE 피드 |
| `POST` | `/agent/completion` | 가벼운 단발 completion (세션 없음) |
| `POST` | `/agent/list-models` | 프로바이더 모델 introspection |
| `GET` | `/agent/events` | 세션 이벤트 SSE 스트림 |

## 권한

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `POST` | `/agent/permission-request` | Blocking: 요청 제출 후 결정 대기 |
| `POST` | `/agent/permission-respond` | UI 쪽: 승인 또는 거부 |
| `GET` | `/agent/permission-pending` | Pending 나열 (전역 또는 세션별) |

## Chat (정규화 히스토리 표면)

| 메서드 | 경로 | 용도 |
|--------|------|------|
| `GET` | `/chat/sessions` | DB의 chat 세션 나열 |
| `POST` | `/chat/sessions` | chat 세션 생성 |
| `DELETE` | `/chat/sessions/:id` | chat 세션 삭제 |
| `GET` | `/chat/sessions/:id/messages` | 메시지 나열 (`since`, `limit`) |
| `POST` | `/chat/sessions/:id/messages` | chat 메시지 추가 |
| `DELETE` | `/chat/sessions/:id/messages` | 메시지 비우기 |
| `GET` | `/chat/images/:sessionId/:filename` | embed 제공 |

## 응답 모양

모든 응답은 같은 봉투를 따른다. `server/api-types.ts`에서 생성되므로
HTTP와 WS가 드리프트할 수 없음:

```ts
type ApiResponse<T> =
  | { status: "ok"; data: T }
  | { status: "error"; message: string; code?: string };
```

이벤트를 emit하는 라우트(start, send, run-once)는 세션의 이벤트
버퍼로 푸시한다. 읽으려면 WS나 SSE로 구독한다.

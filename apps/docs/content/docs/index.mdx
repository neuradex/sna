SNA (Skills-Native Application) is an SDK for building products on top of
agent runtimes. It spawns Claude Code, Codex, or OpenCode as a managed
subprocess and exposes a single API surface — one session model, one
event protocol, one permission flow — so a consumer app can swap or
mix runtimes without rewriting the integration.

```
your app  →  @sna-sdk/client  →  SNA server  →  spawn(claude-code | codex | opencode)
                                       ↑
                                   events back over WS
```

## Why SNA

- **One canonical conversation model.** Messages live as flat blocks
  (`actor` × `kind`); provider-native formats (Anthropic content arrays,
  Codex `ResponseItem`s, OpenCode parts) are derived on demand.
- **3-layer attribution.** `provider` × `modelProvider` × `model`. Swap
  runtimes mid-session and per-row attribution stays honest.
- **Unified permission flow.** Claude Code's PreToolUse hook and
  Codex's JSON-RPC approval are abstracted behind one API.
- **Runtime control without restart.** Change model, permission mode,
  cwd, or interrupt mid-turn. Restart and resume rebuild
  provider-native history from canonical blocks.
- **One-shot completions.** `completion()` and `runOnce()` skip the
  session machinery for short single-prompt jobs (naming a chat,
  autocomplete preview), with optional streaming callbacks.

SNA は会話履歴を SQLite 内の **正規化ブロック** のフラットシーケンス
として保存します。各ブロックは 2 つの直交軸を持ちます:

- `actor`: `user` | `assistant` | `system`
- `kind`: `text` | `thinking` | `tool_use` | `tool_result` | `status` | `error`

バイナリコンテンツ (画像、ファイル) は id をキーにした別の `embeds`
JSON に置かれ、ブロックの `content` テキストには `![](embed://<id>)`
のインライン参照が入ります。プロバイダネイティブの形 (Anthropic content
配列、Codex `ResponseItem`、OpenCode parts) は **要求時に派生** され
るもので、真実の源ではありません。

## なぜフラットブロックか

ほとんどのプロバイダは text、tool_use、thinking を 1 つの "message"
オブジェクトにまとめるネストしたメッセージ形式を提供します。単一プロ
バイダでは問題になりにくい一方で、クロスプロバイダ replay では複雑に
なります。プロバイダごとに順序、signature、optional フィールドの
ルールが少しずつ異なるためです。

フラットブロックリストは 3 つのランタイムすべてで round-trip 可能な
最小の表現です。各プロバイダのアダプタがフラットリストを歩いて、
そのプロバイダが期待するネストした形を再構築します。

`actor` と `kind` の設計背景は **[Actor と kind](/ja/docs/introduction/philosophy/actor-kind)** を
参照してください。

## Replay アダプタ

| パス | アダプタ |
|------|----------|
| `claude-code` resume | `history/claude-code.ts` (`thinking.signature` を保持する JSONL) |
| `codex` resume | `history/codex.ts` (`thread/resume` と `ResponseItem[]`) |
| `opencode` resume | `history/opencode.ts` (prompt-prelude 再構成) |

`POST /agent/resume` は、新たに spawn したプロセスに履歴を replay
する経路です。入力はセッション id と正規化ブロックだけで、アダプタが
プロバイダ固有の罠 (signature フィールド、tool_use 順序、partial-text
の合体) をすべて処理します。

## 3 層アトリビューション

すべてのブロックは 3 つのアトリビューション次元を記録します。

- `provider`: ブロックを作ったランタイム (claude-code / codex / opencode)
- `modelProvider`: モデルを所有したベンダ (anthropic / openai / google)
- `model`: 正確なスラッグ (`claude-sonnet-4-6`、`gpt-5.4` 等)

これによって、ユーザがスレッド途中でプロバイダを切り替えても行ごとの
真実を失わず、UI が「ここで Codex の gpt-5.4 に切り替えました」と
表示できます。

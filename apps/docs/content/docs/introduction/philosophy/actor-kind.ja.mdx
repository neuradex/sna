---
title: Actor と kind
description: SNA がメッセージをプロバイダ中立の actor と kind フィールドで正規化する理由です。
icon: Blocks
---

SNA は、OpenAI 形式または Anthropic 形式のどちらかを内部の真実の源に
することもできました。しかし、この 2 つの形式は単にフィールド名が
違うだけではありません。ツール呼び出しの並列処理、role の意味、
thinking や tool result の表現方法がそれぞれ異なります。どちらか一方の
モデルをそのまま採用すると、もう一方のプロバイダの意味を無理に押し込む
ことになります。

SNA の哲学は、各ネイティブエージェントが提供する豊富な機能を最大限に
活用することです。あるランタイムで機能が足りない場合でも、可能な範囲で
ワークアラウンドを用意し、同じ種類の作業を実行できるようにします。
そのため、正規化レイヤは特定プロバイダの wire shape を複製する層では
なく、複数ランタイムの良い点を保ちながら、どちらにも偏らない中立的な
層である必要があります。

`actor` と `kind` を分けている理由もここにあります。`actor` は誰がその
ブロックを作ったかを表し、`kind` はそのブロックが何を意味するかを表します。
OpenAI と Anthropic の role 体系はそれぞれの API では自然ですが、SNA が
扱うクロスプロバイダ履歴では十分に中立的ではありません。そのため SNA は、
両方の良い点を取り込みつつ、どちらか一方の role モデルを内部標準にしない
ように意図して設計されています。

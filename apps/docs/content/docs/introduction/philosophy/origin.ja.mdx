---
title: 出発点
description: SNA がコーディングエージェントをまたぐランタイム層として始まった理由です。
icon: Sparkles
---

SNA の出発点は単純でした。Claude Code と Codex を行き来しながら作業する
うちに、有用な資産が別々のツール、セッション、インターフェースに散らばる
ことが痛みとして見えてきました。作業そのものは移動できても、その周辺の
文脈は自然には一緒に移動しませんでした。そこで、コーディングエージェント
の間をストレスなく行き来できるようにしたいと考えました。

各コーディングエージェントには、CLI としてすでに優れた部分がありました。
しかし、すべてのワークフローにとって CLI が最適なインターフェースである
わけではありません。優れている部分がある一方で、より良い連続性、可視性、
制御を持つ独自の GUI を作りたいと思わせる部分もありました。

きっかけは VS Code の Claude Code 拡張機能でした。見た目は Claude Code
ですが、ターミナル内の CLI そのものではありませんでした。「これは CLI では
ないのに、どうやって作られているのか」という疑問が生まれ、そこから Claude
Code のオプションやランタイム表面を調べ始めました。その調査を通じて、
Claude Code をプログラムから統合でき、Codex も同じアプリ向けの層の背後に
並べられることが分かりました。

SNA はその観察から始まりました。ネイティブなコーディングエージェントは
それぞれの強みを保つべきですが、連続性はアプリが所有すべきです。セッション、
履歴、権限、UI、ランタイム切り替えが別々のツールに散らばっていてはいけません。

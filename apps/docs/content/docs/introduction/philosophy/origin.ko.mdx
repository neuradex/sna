---
title: 출발점
description: SNA가 코딩 에이전트를 넘나드는 런타임 계층으로 시작된 이유입니다.
icon: Sparkles
---

SNA의 출발점은 단순했습니다. Claude Code와 Codex를 오가며 작업하다 보니,
유용한 자산이 서로 다른 툴, 세션, 인터페이스에 흩어지는 것이 페인포인트로
다가왔습니다. 작업은 이동할 수 있었지만, 그 주변의 맥락은 자연스럽게 함께
이동하지 않았습니다. 그래서 코딩 에이전트 사이를 스트레스 없이 넘어다니고
싶었습니다.

각 코딩 에이전트는 CLI로서 이미 훌륭한 부분이 있었습니다. 하지만 모든
워크플로에 CLI가 가장 좋은 인터페이스인 것은 아니었습니다. 어떤 부분은
뛰어났지만, 어떤 부분은 더 나은 연속성, 가시성, 제어를 제공하는 독자적인
GUI를 만들고 싶게 했습니다.

계기는 VS Code의 Claude Code 확장 기능이었습니다. 겉으로는 Claude Code처럼
보였지만, 터미널 안의 CLI만은 아니었습니다. "저건 CLI가 아닌데 어떻게
만든 걸까?"라는 질문이 생겼고, 그때부터 Claude Code의 옵션과 런타임 표면을
뒤지기 시작했습니다. 그 조사 과정에서 Claude Code를 프로그래밍적으로
통합할 수 있고, Codex도 같은 앱용 계층 뒤에 함께 둘 수 있다는 것을
알게 되었습니다.

SNA는 그 관찰에서 시작되었습니다. 네이티브 코딩 에이전트는 각자의 강점을
유지해야 하지만, 연속성은 앱이 소유해야 합니다. 세션, 히스토리, 권한, UI,
런타임 전환이 서로 다른 툴에 흩어져 있지 않아야 합니다.

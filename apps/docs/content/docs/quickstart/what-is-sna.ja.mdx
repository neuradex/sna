**SNA** (*Skills-Native Application*) はエージェントランタイムの上に
プロダクトを作るための SDK だ。LLM API を直接呼ぶ代わりに、アプリは
小さなサーバに話しかけ、そのサーバが長期稼働の **Claude Code**、
**Codex**、または **OpenCode** プロセスを管理する。SNA はこの 3 つ
すべてに対して 1 つの正規化された API を提供する。

## 構造

```
your app
   │
   │  HTTP (request/response, ordering)
   │  WS   (live events, fanout)
   ▼
SNA server  ──spawn──►  claude-code | codex | opencode
   │
   ▼
SQLite (canonical history)
```

サーバを 1 つ起動し、**セッション** を 1 つまたは複数開く。各
セッションで実際の CLI バイナリ（`claude`、`codex`、`opencode`）
が子プロセスとして spawn される。SNA は各ランタイムのイベント、
履歴、権限モデルを 1 つの形に正規化するので、コンシューマアプリは
プロバイダごとに分岐する必要がない。

## どんな問題を解くのか

公式 LLM API はステートレスな completion には合うが、プロダクトが
次のようなものを必要とした瞬間に話が変わる:

- **ツール、ファイル編集、承認のある長期稼働エージェント**: 結局
  Claude Code や Codex のループを自分で再実装することになる。
- **同じエージェントを別のランタイムで**（コード編集は Claude、
  画像生成は Codex、コストは OpenCode）: 切り替えるたびに統合
  コードを書き直すことになる。
- **ランタイム切り替えに耐える会話履歴**: ネイティブフォーマット
  は相互運用しないので、プロバイダを 1 つに決め打つか、切り替え
  のたびに文脈を失うかのどちらか。
- **ユーザに同じに見える権限フロー**: Claude の PreToolUse フック
  と Codex の JSON-RPC 承認はプロトコルも UX も異なる。

SNA はこれらすべてに対して *"本物の CLI を使う"* を真剣な答えに
する。CLI 群はすでに難しい部分（ツールディスパッチ、サンドボックス、
権限ゲート、履歴）を全部やっている。SNA はそれらをラップして、
1 つのコンシューマ側コードベースで 3 つのランタイムすべてに対応
できるようにする。

## 得られるもの

- **1 つの正規化された会話モデル.** メッセージは 2 つの直交軸を
  持つフラットブロックとして保存される: `actor`
  (`user`/`assistant`/`system`) × `kind`
  (`text`/`thinking`/`tool_use`/`tool_result`/`status`/`error`)。
  プロバイダネイティブの形はここから必要時に派生する。
- **3 層アトリビューション.** すべてのブロックが `provider`
  (ランタイム)、`modelProvider` (ベンダ)、`model` (スラッグ) を
  記録する。セッション途中で何を切り替えても行ごとの真実が保たれる。
- **正規化されたイベントプロトコル.** WebSocket または SSE 上の
  15 種類のイベントタイプ: `assistant_delta`、`tool_use`、
  `permission_needed`、`complete` など。
- **正規化された権限フロー.** 1 つの API が Claude の PreToolUse
  フックと Codex の JSON-RPC 承認の両方を露出する。コンシューマ
  アプリの承認ダイアログはプロバイダで変わらない。
- **再起動不要のランタイム制御.** スレッド途中でモデル、権限
  モード、作業ディレクトリを変更可能。Restart と resume が正規化
  ブロックからプロバイダネイティブ履歴を再構築する。
- **一級の単発 API.** `completion()` と `runOnce()` はセッション
  機構なしの単発呼び出し用。自動補完やチャット命名のような短い
  単一プロンプト作業に。ストリーミングコールバックもオプション。

## 誰のためのもの

- **エージェント CLI の上にチャットや copilot を載せるプロダクト
  ビルダー.** SNA は統合境界だ: アプリは UI を、SNA はランタイム
  配管を担当する。
- **マルチランタイムアプリ.** Claude Code、Codex、OpenCode の中
  からユーザに選ばせたい（または自動ルーティングしたい）が、
  プロバイダごとに統合コードを分岐させたくない場合。
- **Electron / デスクトップアプリ.** エージェントをローカルに
  組み込む。ローンチャがサーバを子プロセスとして fork し、
  asar-unpacked パスを処理し、ネイティブバインディングを探す。

## *これではない* もの

- **ホスト型 LLM エンドポイントではない.** SNA は自身が動くホスト
  上で本物の CLI を spawn する。バイナリと認証情報はユーザが提供。
- **エージェントフレームワークではない.** エージェントの作り方は
  教えない。それは Claude Code / Codex / OpenCode の仕事で、SNA
  はアプリがそれらを動かせるようにする層だ。
- **下層 CLI の挙動を隠すラッパーではない.** Claude Code がファイル
  を編集したら、実際の編集が見える。Codex が画像を生成したら本物
  のファイルパスが返る。SNA は形を正規化するが、意味は正規化しない。

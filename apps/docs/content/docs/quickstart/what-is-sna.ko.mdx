**SNA** (*Skills-Native Application*)는 에이전트 런타임 위에 제품을
만들 때 쓰는 SDK다. LLM API를 직접 호출하는 대신, 앱이 작은 서버에
말을 걸면 그 서버가 장기 실행되는 **Claude Code**, **Codex**,
**OpenCode** 프로세스를 관리한다. SNA는 이 셋 전부에 통하는 하나의
정규화된 API를 제공한다.

## 구조

```
your app
   │
   │  HTTP (request/response, ordering)
   │  WS   (live events, fanout)
   ▼
SNA server  ──spawn──►  claude-code | codex | opencode
   │
   ▼
SQLite (canonical history)
```

서버 하나를 띄우고 **세션**을 한 개 또는 여러 개 연다. 세션마다 실제
CLI 바이너리(`claude`, `codex`, `opencode`)가 자식 프로세스로 spawn
된다. SNA는 각 런타임의 이벤트, 히스토리, 권한 모델을 하나의 모양으로
정규화하므로 소비자 앱이 프로바이더별로 분기할 필요가 없다.

## 어떤 문제를 푸는지

공식 LLM API는 무상태 completion에는 잘 맞지만, 다음 같은 요구가
생기는 순간 골치가 아파짐:

- **툴, 파일 편집, 승인이 있는 장기 실행 에이전트**: 결국 Claude
  Code나 Codex의 루프를 직접 재구현하게 됨.
- **같은 에이전트를 다른 런타임으로** (코드 편집은 Claude, 이미지
  생성은 Codex, 비용은 OpenCode): 교체할 때마다 통합 코드가 다시
  쓰여진다.
- **런타임 교체에도 살아남는 대화 히스토리**: 네이티브 포맷들이 서로
  호환 안 되니, 하나의 프로바이더를 평생 쓰거나 교체할 때마다 맥락을
  잃거나 둘 중 하나.
- **유저에게 같은 모양으로 보이는 권한 흐름**: Claude의 PreToolUse
  훅과 Codex의 JSON-RPC 승인은 프로토콜도 UX도 다름.

SNA는 *"진짜 CLI를 그대로 쓴다"* 를 이 모든 것에 대한 진지한 답으로
삼는다. CLI들은 이미 어려운 일(툴 디스패치, 샌드박싱, 권한 게이팅,
히스토리)을 다 한다. SNA는 그걸 감싸서 하나의 소비자 코드베이스가
세 런타임 모두에서 돌아가게 한다.

## 무엇을 받게 되는지

- **하나의 정규화된 대화 모델.** 메시지는 두 축의 평탄한 블록으로
  저장된다: `actor` (`user`/`assistant`/`system`) × `kind`
  (`text`/`thinking`/`tool_use`/`tool_result`/`status`/`error`).
  프로바이더 네이티브 모양은 필요할 때 여기서 파생된다.
- **3계층 어트리뷰션.** 모든 블록이 `provider` (런타임),
  `modelProvider` (벤더), `model` (슬러그)을 기록함. 세션 도중 어떤
  걸 바꿔도 행 단위 진실이 유지된다.
- **정규화된 이벤트 프로토콜.** WebSocket 또는 SSE 위 15가지 이벤트
  타입: `assistant_delta`, `tool_use`, `permission_needed`,
  `complete` 등.
- **정규화된 권한 흐름.** 하나의 API가 Claude의 PreToolUse 훅과
  Codex의 JSON-RPC 승인 양쪽을 모두 노출함. 소비자 앱의 승인
  다이얼로그는 프로바이더에 따라 안 바뀐다.
- **재시작 없이 런타임 제어.** 스레드 도중 모델, 권한 모드, 작업
  디렉토리를 바꿀 수 있음. Restart와 resume이 정규화 블록에서
  프로바이더 네이티브 히스토리를 재구성한다.
- **일급 단발 API.** `completion()`과 `runOnce()`는 세션 기계 장치
  없이 단발 호출용. 자동완성, 채팅 이름 짓기 같은 짧은 단일 프롬프트
  작업에. 스트리밍 콜백도 옵션.

## 누구를 위한 것

- **에이전트 CLI 위에 채팅/코파일럿을 올리는 제품 빌더.** SNA는
  통합 경계선이다: 앱은 UI를, SNA는 런타임 배관을.
- **멀티 런타임 앱.** Claude Code, Codex, OpenCode 사이에서 유저가
  고르게(혹은 자동 라우팅) 하고 싶으면서, 프로바이더별로 통합 코드를
  쪼개고 싶지 않은 경우.
- **Electron / 데스크톱 앱.** 에이전트를 로컬에 임베드함. 런처가
  서버를 자식 프로세스로 fork하고, asar-unpacked 경로 처리, 네이티브
  바인딩 위치 찾기까지 함.

## 무엇이 *아닌지*

- **호스팅된 LLM 엔드포인트가 아니다.** SNA는 자신이 도는 호스트에서
  진짜 CLI를 spawn한다. 바이너리와 인증은 사용자가 제공.
- **에이전트 프레임워크가 아니다.** 에이전트를 어떻게 만들지 알려주지
  않는다. 그건 Claude Code / Codex / OpenCode의 일이고, SNA는 앱이
  그것들을 운전할 수 있게 해주는 층이다.
- **밑단 CLI 동작을 숨기는 래퍼가 아니다.** Claude Code가 파일을
  편집하면 실제 편집이 보인다. Codex가 이미지를 생성하면 진짜 파일
  경로를 받는다. SNA는 모양을 정규화하지 의미를 정규화하진 않는다.
